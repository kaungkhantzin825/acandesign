## Clean URLs — removed .php from all public URLs

Chose the **.htaccess rewrite** approach over physically moving pages into `page/index.php`
folders (user confirmed). Nothing moved, so relative asset paths and `include`s stay valid.

- **`.htaccess`** — added a 4-rule mod_rewrite block: `/index.php`→`/`, `/page.php`→`/page`
  (301, **GET only**), `/page/`→`/page` (301), and `/page` served internally by `page.php`.
  Root-level only; `/admin/**` deliberately keeps its `.php` URLs.
  - Keyed on `%{THE_REQUEST}` (not `REQUEST_URI`) so the internal rewrite cannot re-trigger
    the 301 — that is what prevents a redirect loop.
  - POST is excluded so a 301 can't drop the contact-form body.
  - Query strings survive automatically (the substitution contains no `?`).
- **`router.php`** (new) — PHP's built-in server ignores `.htaccess`, so every clean URL
  would 404 locally. Dev command is now `php -S localhost:8000 router.php`.
- **Link conversion** — scripted transform rewrote **142 lines across 25 files**
  (`href`, form `action`, `header('Location: …')`, JS nav). `index.php` links → `/`.
  `include`/`require` left alone on purpose; `admin/**` out of scope.
- **Verified** — 317 internal links resolve to real files; 139 include/require statements
  intact; zero `.php` link references remain outside `admin/`.
- **Caveat:** PHP is not installed in this environment, so verification was static
  (regex + filesystem), **not** a runtime smoke test of the rewrites.
- `CLAUDE.md` updated: Running Locally, file table, new "Clean URLs" section, Deployment.
- `domain-setup-checklist.md` updated: all 301 targets now use clean URLs, and the
  host-keyed brand-domain block must sit **above** the clean-URL block — otherwise
  `acanbpo.jp/service` is served internally instead of redirecting to acan-sol.com.

## Performance pass — all images to WebP + better loading

**Tooling saga (reusable):** no `cwebp` / ImageMagick / PIL; `sips` **cannot** encode WebP.
Installed **Pillow 12.3.0** into `/Users/apple/.workbuddy-ai/binaries/python/envs/default`.
`pip install` failed twice — the sandbox proxy truncates large downloads at ~3.9 MB (the
wheel is 5.3 MB); the first attempt died with SIGKILL. Fix: `curl -L -C -` pulled the whole
wheel in one pass, then `pip install --no-index <wheel>`. **The wheel must keep its real
filename** or pip rejects it with "Invalid wheel filename (wrong number of parts)".

Conversion (370 images; quality 82 JPEG / 85 opaque PNG / 88 PNG-with-alpha — lossy WebP
still carries alpha): **122.2 MB → 15.7 MB (−87%)**.

Findings worth remembering:
- `blog-outsourcing`, `blog-bpo`, `team-meeting` are **SVG content carrying a `.jpg`
  extension**. Renamed to `.svg`; rasterising them would have been a downgrade.
- **`assets/img copy/`** = ~73 unreferenced duplicate images (never converted). Safe to delete.
- The global `main.css` rule `img { max-width:100%; height:auto; }` is what makes adding
  intrinsic `width`/`height` safe — they supply the aspect ratio only, no size change.

Changes:
- 630 image references rewritten (`src=` and `url()`); 4 SVG refs corrected.
- 588 `<img>` tags got loading attributes; 473 got `width`/`height`.
  - eager + `fetchpriority="high"`: `hero__bg-img`, `hero__desktop-logo`, `dl-hero__img`
  - eager: other `hero__*`, `nav__logo`, `site-footer__logo`
  - lazy: everything else — plus `decoding="async"` on all
- `.htaccess`: added `AddType image/webp .webp` (+avif, woff2) and extended Expires to
  avif/ico/woff2/woff/mp4. Documented that assets cache 1 year with **no filename
  fingerprinting**, so replacing an image needs a new filename.
- All 52 Google Fonts links already had `display=swap` — no change needed.
